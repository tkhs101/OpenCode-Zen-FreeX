## Why this fork

[zen-free](https://github.com/magpie-community/plugins/tree/main/packages/zen-free) is this plugin's predecessor. Let's be clear: upstream is maintained, and bugs are fixed quickly. The problem is that it has never had a **stable, explicit position** on **free-model support**.

When a free model stops working, the issue gets the answer that it **will no longer be supported**; some time later the same problem is quietly fixed and the free model works again. Support, drop, support again — users are left churning with upstream's position, never able to tell **how long the support will last**.

If people depend on it, it deserves a clear answer rather than **more flip-flopping** — that is why this project exists.

Later upstream changes are merged as needed, while this branch keeps its own choices (for example, the system prompt and complete tool set are captured per generation from a real OpenCode rather than pinned to one version).

## Installation and login

```sh
magpie plugin add opencode-zen-freex
magpie plugin login opencode-zen-free
```

Use `public` as the key. It is the free tier's shared credential; no personal API key is needed — anything else you enter is discarded.

Personal keys belong in magpie's built-in OpenCode Zen provider: it accepts several keys and switches or fails over between them. Credentials live in OpenCode's `auth.json` or magpie's `plugin-auth.json`.

## Models

Model names are written `opencode-zen-free/<id>`, for example `opencode-zen-free/big-pickle`.

- **Automatic discovery**: when the host lists models, the plugin reads Zen's list; repeated listings within 60 seconds reuse the previous result. A successful read is cached (`~/.cache/opencode-zen-freex/discovery.json`, `%LOCALAPPDATA%` on Windows); when the list cannot be read, the plugin falls back to the cache or the table shipped in the package, and when the cache is used, its age is passed to the host. The protocol table has its own snapshot (`models-observed.json`, published hourly by a repository workflow that diffs OpenCode's docs page, fetched in the background): when the docs cannot be read, or an id's endpoint row was withdrawn, the snapshot or the bundled copy answers, and no model is asked at the wrong endpoint.
- **Limits are measured**: the catalogue, vendor claims and the wall the route actually enforces often disagree. Context is declared at the largest value measured to pass; output prefers the paid twin's declaration on the same gateway. For example, `mimo-v2.6-flash-free`'s catalogue says 200k, but 375k was served; `glm-5.3-flash-free`'s paid twin claims 1M, but 323k was the largest that passed; and the route's own refusals count too — `deepseek-v4.1-flash-free` fell from 1M to 326k after it began refusing above roughly 326,700 tokens. See [`MAINTAINING.md`'s “Limits Zen under-reports”](MAINTAINING.md#limits-zen-under-reports) for the measurements and how to re-run them.
- **Limits are also learned from traffic**: the plugin sends no extra requests; it only probes upward and converges downward with requests it is already forwarding. Learned values survive restarts, and a refused model is pulled back to a size already proven to pass.
- **Measured snapshots without waiting for a release**: the repository runs an incremental sweep every hour, writes `limits-observed.json` and publishes it on `main`; after startup the plugin fetches it in the background at most once per hour, falling back to its cache or the copy in the package.
- **The list is authoritative**: `-free` models on Zen's list are offered immediately (except on protocols this plugin does not support), without waiting for the catalogue; a catalogue that cannot be read only affects what it describes, and does not make the list a fallback.
- **No longer free means 404**: the error lists the models that are free at that moment; once a model is free again, refresh the list. Availability and rate limits belong to Zen; the plugin cannot see remaining quota.

## Requests

Requests go to `https://opencode.ai/inference/v1` in each model's native protocol (Chat Completions / Responses / Anthropic Messages); both streaming and plain JSON are supported.

- **Borrow only OpenCode's shell**: headers, User-Agent, the system prompt and the complete tool set are matched to the current 2.x generation of OpenCode (the 1.x lane was retired by the free tier on 2026-10-25; a retired lane is not something any wording recovers). The official prompt goes in front of the host's own system instructions; a body that already carries it is left alone, so repeated shaping cannot duplicate it. The prompt ends at OpenCode's environment block — no built-in skill is advertised, because a host that is not OpenCode has none of them to load. The requests also have to **leave from a Bun runtime**, as the official clients do: magpie runs its plugins under the Bun it ships, which is what this package rides. The header set is deliberately minimal — **do not add your own**; two individually harmless headers can be refused together.
- **The host's tools still run**: each one keeps its own wording and parameters but travels under a `clint_` name, so it cannot collide with the official set that follows it. Every tool reference in the request is renamed with it, and names in the reply are translated back; the host never sees a name it did not declare. OpenCode's own tools are sent in their complete, captured form — and because the official prompt teaches Code Mode, the prompt is followed by a `<system-reminder>` naming the `clint_` tools this host actually runs, so the model does not open the session by calling `execute` to an unknown-tool error.
- **Unknown tool names go to the host as written**: match exactly first, then case-insensitively, then ignoring `_`/`-`/`.`/whitespace, and accept only a unique result; when nothing matches or the match is ambiguous, the call is neither guessed nor dropped — the model's name, id and arguments reach the host as written, which replies with its own "no such tool"; the model then renames the call and retries. Only calls with no name at all are omitted, and the body says so.
- **One identity is held for a window, one per conversation**: an OpenCode-shaped session id and a project id are minted together, held for 60 seconds by default, and replaced together when the window ends — the timestamp is the current moment, always inside the window the tier accepts. The window is per conversation, not per process: a different name from the host (the CLI sends `x-opencode-session` on every request) is a different pair, so two conversations running at once each hold their own, and a refusal rotates only the conversation it refused. A request that names nothing shares one slot — requests nothing can tell apart are requests the tier cannot tell apart either. Bursts of fresh identities are refused where the same requests spaced about half a second apart pass (measured). `OPENCODE_ZEN_FREE_IDENTITY_TTL_MS=0` mints a fresh pair per request instead, which is also what measuring one ledger needs. Set `OPENCODE_ZEN_FREE_SESSION_AFFINITY=1` for one session per conversation kept indefinitely (an OpenCode-shaped id from the host passed through; otherwise one derived from the host's session identifiers and remembered, so every turn shares an id), where the window is not consulted.
- **The project id is its own too**: the shared `public` credential identifies no one, so quota has nothing to do with the key — it is ledgered along the dimensions that do distinguish traffic: an egress-IP budget, and per-(project id × egress) ledgers beneath it. While the egress has room, a fresh id on a spent exit is a new ledger (measured 2026-10-26); on a popular exit the egress budget is spent by everyone routed through the same IP, and no fresh id opens anything: a ~32k-token request refused five times, then a ~5k one five more, and two such rounds after those — twenty fresh ids, one answer: 429 (measured 2026-10-27 on a US exit whose admission probe had just passed — our own spend there in the minutes in between was ~10k tokens, so the exhaustion was the world's, not ours). On a saturated exit, waiting is what helps. A host that names its project keeps that name across windows; one that does not gets a random git-hash-shaped id held for the window above — the old `global` default was one bucket shared by every freeriding plugin user on the planet, pre-burned on popular exits.
- **Truncation and errors are reported honestly**: if a stream ends early, a Chat stream with content and no unfinished tool call is completed as a normal answer marked truncated; anything else fails. The error body is read only far enough to find a limit Zen itself states; the rest is replaced with an explanation.

<details>
<summary>Full rules for headers and session ids</summary>

**Headers** are exactly: `content-type`, `accept`, `user-agent`, `x-opencode-project`, `x-opencode-session` and `x-opencode-session-id` (the same value), `x-opencode-client: cli`, `authorization: Bearer public`; Messages uses `x-api-key: public` plus `anthropic-version` instead. The plugin never sets `anthropic-beta` itself — it passes it through only when the host sends it.

**Session id**: the default holds one session for the window and reads none of what follows; `OPENCODE_ZEN_FREE_IDENTITY_TTL_MS=0` gives a fresh one per request. With `OPENCODE_ZEN_FREE_SESSION_AFFINITY=1`, the conversation is named in order from the session headers `x-opencode-session` / `x-opencode-session-id` / `x-session-affinity` / `x-session-id` / `session_id` / `conversation-id` / `conversation_id`, then the body's `conversation_id`, `metadata.session_id`, or the `_session_<uuid>` inside Claude Code's `metadata.user_id`. If none of those exists, the system/instructions and the first user message form the seed (a changed system prompt is a different conversation); only after that is `previous_response_id` consulted, and failing that a new id is generated every time. An empty string is never a name.

</details>

## When the free tier stops answering

The 403 this plugin returns names the OpenCode version its prompt and tool definitions were captured from; start there. All three commands **run only in a repository checkout** (`check:gate` and `capture` are not in the published package) and need Bun; `capture` also needs `opencode` on PATH:

```sh
bun run check:gate          # which fingerprints Zen accepts; 0 if a floor answers
bun run capture -- --dry    # all floors refused: capture, report the diff, write nothing
bun run capture             # write only after confirming the diff
```

`capture` rewrites `fingerprint.json` rather than refusing when the file is missing or broken. It does not write the prompt or the complete tool set: those live in `opencode-prompt-v1.txt` and `official-tools.json`, and a release updates them from the same OpenCode version as the capture (see [`MAINTAINING.md`](MAINTAINING.md#the-loop)). The gate is not stable: a verdict describes this moment only, so run it again before trusting it; repeated refusals from one address can also trigger a cooldown. For per-generation verdicts and how to read a failure, see [`MAINTAINING.md`'s “The loop”](MAINTAINING.md#the-loop) and [“Reading a failure”](MAINTAINING.md#reading-a-failure).

## Troubleshooting

| Symptom | What to do |
| --- | --- |
| Every request is `403 FreeTierError`, with no egress-block wording | The captured OpenCode shape is stale. Update the plugin; from a repository checkout run `bun run check:gate`, and if every floor is refused, recapture the profile and refresh the prompt/tool assets from the same release |
| The `403` body is a block notice (`abuse of traffic`, or `free models aren't available … from your current network`) | The free tier is blocking the current egress. Wait for the block to lift; retrying or rewriting the request will not help |
| `426 Upgrade Required` | The package claims an older OpenCode version than Zen wants. Update the plugin, or run inside a newer OpenCode |
| `404 … not available as an OpenCode Zen free model now` | Zen no longer offers this model for free. Pick another from the models listed in the error |
| `Model is not an available free model for this protocol` | The list changed after the request was sent. Refresh the host's model list and retry |
| `uses the public credential` | The stored key is not `public`. Log in again with `public` |
| A `403` without `FreeTierError` | It is Zen's own 403, not this plugin's; read it as sent |
| `400 context_length_exceeded`, or `max_tokens` out of range | The route enforces the model's own limits. Compact the conversation or lower `max_tokens`; context refusals state no window, while `max_tokens` refusals do state the allowed range |
| The window looks too small and you want it re-learned, or a new environment variable has no effect | Delete `opencode-zen-freex/limits.json` under the cache directory (see Environment variables for where); environment variables are read only when the host starts, so restart it |
| A model is asked for the wrong protocol | The endpoint table in the protocol docs could not be read. Set `OPENCODE_ZEN_FREE_MODELS_DEBUG=1` to see which document failed and why |
| You want to check snapshot freshness or whether a model was retired | From a repository checkout run `bun limits-watch.mjs --status`; exit 0 is healthy, 2 is read but has issues, 1 is unreadable. `unavailable` is history only, not a disable switch |
| The window stays at an old value, or `raw.githubusercontent.com` is unreachable | The remote snapshot is only an optimisation; a failure does not affect requests. Point it elsewhere or turn it off with the environment variables (see Environment variables) |

## Environment variables

Common ones only; the full list and defaults are in [`.env.example`](https://github.com/tkhs101/OpenCode-Zen-FreeX/blob/main/.env.example). The cache directory is `%LOCALAPPDATA%` on Windows, and `$XDG_CACHE_HOME` or `~/.cache` elsewhere.

| Variable | Purpose |
| --- | --- |
| `OPENCODE_ZEN_FREE_DISCOVERY_CACHE` | Discovery cache path; an empty string keeps discovery in memory only |
| `OPENCODE_ZEN_FREE_SESSION_AFFINITY` | `1` keeps one session per conversation instead of the identity window |
| `OPENCODE_ZEN_FREE_IDENTITY_TTL_MS` | Milliseconds one session and project id are held before both are replaced; default `60000` (60 seconds); `0` mints a fresh pair per request; capped at `86400000` |
| `OPENCODE_ZEN_FREE_RETRY_429` | 429 retry count, default `2`; `0` turns the retry off |
| `OPENCODE_ZEN_FREE_RETRY_WAIT_MS` | Milliseconds before the first retry, default `1200`, doubling per attempt |
| `OPENCODE_ZEN_FREE_RETRY_WAIT_MAX_MS` | Wait ceiling, default `5000`; deliberately short by default — deployments that need longer set their own |
| `OPENCODE_ZEN_FREE_RETRY_AFTER` | `1` honours a 429's own `retry-after` window (replaces one attempt's wait, still capped at 120 s); ignored by default |
| `OPENCODE_ZEN_FREE_PACING_MS` | Smallest gap in milliseconds between two requests this loader sends; default `0` (off), capped at `30000` |
| `OPENCODE_ZEN_FREE_MODELS_SNAPSHOT` | Bundled protocol-snapshot path; an empty string disables the bundled copy |
| `OPENCODE_ZEN_FREE_MODELS_SNAPSHOT_URL` | Remote protocol-snapshot URL; an empty string disables the remote |
| `OPENCODE_ZEN_FREE_MODELS_SNAPSHOT_CACHE` | Remote protocol-snapshot cache path; an empty string keeps it in memory only |
| `OPENCODE_ZEN_FREE_MODELS_SNAPSHOT_REFRESH_MS` | Remote protocol-snapshot refresh interval, default `3600000` |
| `OPENCODE_ZEN_FREE_MODELS_SNAPSHOT_TIMEOUT_MS` | Remote protocol-snapshot fetch timeout, default `5000` |
| `OPENCODE_ZEN_FREE_LIMITS_SNAPSHOT` | Measured-snapshot path; an empty string disables reading a snapshot |
| `OPENCODE_ZEN_FREE_LIMITS_SNAPSHOT_URL` | Remote snapshot URL; an empty string disables the remote |
| `OPENCODE_ZEN_FREE_LIMITS_STATE` | Path to the learned-limit state; an empty string keeps it in memory only |
| `OPENCODE_ZEN_FREE_LIMITS_DEBUG` | Set to `1` to log every raise, refusal, and route-stated window to stderr |
| `OPENCODE_ZEN_FREE_MODELS_DEBUG` | Set to `1` to print catalogue-parsing details |
| `OPENCODE_ZEN_FREE_MAX_WINDOW` | Upper bound for upward probing; defaults to `1048576` |
